General-Purpose Reasoning Core

A reasoning engine with no language model and no machine learning. Every part of how it reasons was written by hand.

contents:
01 / The original plan 02 / How the core works 03 / Handling mistakes 04 / Built vs. scaled

AETHER is a reasoning engine that contains no language model, and no machine learning in the traditional sense. There is no training data, no neural network, and no next-word prediction.

Every part of how it reasons, decides, and responds was written by hand, as code, curated by me. Because of this it cannot hallucinate, because it does not predict. It says what it knows and what it doesn't know. It is simply executing written logic.

AETHER Autonomous Expression Through Hallucination-Eliminated Reasoning.

Most AI systems are grown, not built. A neural network is fed large amounts of data until useful behavior emerges. Nobody designs that behavior directly. Nobody can fully explain a given output. The system's own creators cannot guarantee its behavior. Maybe for some applications that is the point, but not for the ones I have in mind.

AETHER is built the opposite way. Every capability is written by hand. Nothing is learned through training. The system's goals, its reasoning, and its corrections are explicit and readable, because I wrote them that way.

The original plan

The original plan was one system with knowledge covering every domain. A single system you could ask about anything. That plan was abandoned.

What replaced it: one reasoning core, reused across separate domain-specific applications. Legal work. Medical use. Control of a prosthetic sleeve (I'll write about that one soon). Each application only knows its own domain — narrow by design. None of them are general on their own.

How the reasoning core works

AETHER is made of narrow engines. Each engine solves one scoped problem: abstraction, causal chaining, consequence tracing, analogy detection. None of these engines know anything about law, medicine, or prosthetics.

A new application is built by giving this same set of engines new knowledge and new constraints for that domain. The engines themselves are not retrained or rewritten. Only the domain layer changes.

This means the reuse is architectural. The same reasoning steps run underneath every application. What differs is the knowledge and rules loaded on top.

Handling mistakes

A trained model corrects itself by adjusting internal values across a network. The correction is distributed across millions of numbers. Nobody can point to what changed.

Aether handles mistakes differently. A mistake is classified, and a rule is written down. Example: if a recommendation ignores an important user constraint, the system records a rule to check for that constraint before generating future recommendations. That rule is checked before the system acts again.

THE DIFFERENCE The fix is a sentence, not a weight update.

The same applies to the system's core goals: honesty, doing no harm. These are written once, by hand, and are not altered automatically. They can be extended for a specific session, but they do not drift on their own.

Built vs. scaled

In generative AI, capability is something that shows up once a model is scaled up enough. My architecture treats capability as something assembled on purpose, from a fixed set of reasoning methods, applied to whatever domain knowledge is loaded in.

Every part of the system can be inspected on its own. Nothing about its behavior depends on a process nobody controls.

That's what AETHER is: a system built rather than trained. It can be explained, and its behavior can be changed with a single edit, rather than retraining the whole thing.
